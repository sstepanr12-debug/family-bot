# Семейный календарь — Telegram Mini App

Общее расписание семьи внутри Telegram: открыл приложение — увидел неделю, добавил
событие, у всех участников оно появилось сразу, без перезагрузки.

- **Frontend** — React + TypeScript + Vite, официальный Telegram WebApp API, тема
  подхватывается из Telegram.
- **Backend** — Node.js + Express + TypeScript, Prisma (SQLite по умолчанию,
  PostgreSQL одной строкой), Socket.io для мгновенной синхронизации.
- **Бот** — уведомления о новых событиях и напоминания перед началом (node-cron).

## Быстрый старт

```bash
cd family-calendar
cp .env.example backend/.env
npm install
npm run db:push       # создаёт SQLite-базу по схеме Prisma
npm run dev           # backend :3000 + frontend :5173
```

Откройте http://localhost:5173. Пока `BOT_TOKEN` пуст и `DEV_FAKE_USER=1`, вход
происходит под фиктивным пользователем — приложение полностью работает в обычном
браузере. Чтобы открыть вторую вкладку как другого участника, добавьте `?dev=2`
(и присоединитесь к семье по коду приглашения).

Тесты:

```bash
npm test
```

Покрыты проверка `initData`, CRUD событий с правами доступа и разворачивание
повторяющихся событий.

## Переменные окружения

Все переменные — в `backend/.env` (шаблон: `.env.example` в корне проекта).

| Переменная | Назначение |
| --- | --- |
| `PORT` | Порт API (по умолчанию 3000) |
| `DATABASE_URL` | `file:./dev.db` для SQLite либо `postgresql://…` |
| `JWT_SECRET` | Секрет для подписи сессионных токенов — обязательно свой |
| `BOT_TOKEN` | Токен бота из BotFather. Пустой = уведомления выключены |
| `DEV_FAKE_USER` | `1` — вход без Telegram (только вне production) |
| `PUBLIC_URL` | Публичный HTTPS-адрес — по нему регистрируется вебхук бота |
| `WEBHOOK_SECRET` | Секретный сегмент пути вебхука, длинная случайная строка |
| `CORS_ORIGIN` | Дополнительные разрешённые источники, через запятую |
| `VITE_API_URL` | Пусто = API на том же адресе. Заполнять только при раздельном хостинге |

В `NODE_ENV=production` пустой `BOT_TOKEN` останавливает запуск: без него нельзя
проверить подлинность `initData`.

## Регистрация бота в BotFather

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot`, задайте имя и
   username. Полученный токен положите в `BOT_TOKEN`.
2. `/newapp` (или `/myapps` → Bot Settings → Configure Mini App) → выберите бота,
   укажите название, описание, картинку 640×360 и **HTTPS-URL приложения**.
3. `/setmenubutton` → выберите бота → тот же URL и подпись кнопки, например
   «Календарь». Теперь Mini App открывается из меню чата с ботом.
4. Чтобы участники получали уведомления, каждый должен один раз нажать `/start`
   у бота — иначе Telegram не разрешает боту писать первым.

### Проверка на своём компьютере через туннель

Telegram открывает Mini App только по HTTPS, поэтому локальный сервер нужно
пробросить наружу. Бэкенд отдаёт и API, и собранный фронтенд, так что туннель
нужен один:

```bash
npm run build
npx cloudflared tunnel --url http://localhost:3000
```

Полученный `https://…trycloudflare.com` впишите в `backend/.env` как
`PUBLIC_URL`, запустите `npm start` и укажите тот же адрес в BotFather. Работает,
пока включён компьютер и жив туннель — для постоянной работы см. «Деплой».

## Деплой: бесплатный вариант (Render + Neon)

Бэкенд отдаёт собранный фронтенд с того же адреса, поэтому нужен **один** сервис
и один HTTPS-URL — ровно то, что требует Telegram.

### 1. База данных — Neon (бесплатно)

1. Зарегистрируйтесь на [neon.tech](https://neon.tech), создайте проект.
2. Скопируйте connection string вида
   `postgresql://user:pass@ep-….neon.tech/neondb?sslmode=require`.

Бесплатный проект Neon засыпает при простое и просыпается меньше чем за секунду —
для семейного календаря это незаметно.

### 2. Приложение — Render (бесплатно)

1. Залейте проект на GitHub (или подключите репозиторий, где он лежит).
2. На [render.com](https://render.com) → **New → Web Service** → ваш репозиторий.
   Если Render найдёт `render.yaml`, все настройки подхватятся сами; иначе
   задайте вручную:
   - Build Command: `npm ci && npm run db:postgres && npm run build`
   - Start Command: `npm start`
   - Plan: Free
3. Переменные окружения (Environment):

   | Переменная | Значение |
   | --- | --- |
   | `NODE_ENV` | `production` |
   | `DEV_FAKE_USER` | `0` |
   | `DATABASE_URL` | строка подключения из Neon |
   | `BOT_TOKEN` | токен из BotFather |
   | `JWT_SECRET` | любая длинная случайная строка |
   | `WEBHOOK_SECRET` | любая длинная случайная строка |
   | `PUBLIC_URL` | `https://<имя-сервиса>.onrender.com` |

   `PUBLIC_URL` известен только после первого деплоя — задайте его вторым шагом
   и перезапустите сервис. На старте приложение само зарегистрирует вебхук бота.
4. Укажите этот же URL в BotFather (`/setmenubutton` и Mini App), см. ниже.

### Ограничение бесплатного тарифа Render

Бесплатный сервис засыпает после ~15 минут без запросов: первое открытие после
сна ждёт ~40–50 секунд, а напоминания в это время не отправляются (планировщик
спит вместе с процессом). Уведомления о **новых событиях** не теряются: сообщение
боту приходит вебхуком, который сервис и будит.

Чтобы напоминания были надёжными, держите сервис бодрым внешним пингом: на
[cron-job.org](https://cron-job.org) (бесплатно) создайте задание, которое раз в
10 минут запрашивает `https://<ваш-адрес>/api/health`. Бесплатных 750 часов
Render хватает ровно на один непрерывно работающий сервис.

Если понадобится по-настоящему без оговорок — тот же репозиторий разворачивается
на Railway или любом VPS без единой правки кода: там процесс не засыпает.

### VPS с Nginx

Соберите проект (`npm ci && npm run build`), запускайте `npm start` под systemd,
проксируйте `/` на `localhost:3000` (для WebSocket нужны заголовки
`Upgrade`/`Connection`), сертификат — через certbot.

### Переход на PostgreSQL вручную

`npm run db:postgres` переключает провайдер в `prisma/schema.prisma`, обратно —
`npm run db:sqlite`. Модели менять не нужно; `npm start` сам выполняет
`prisma db push` перед запуском.

## Как устроен код

```
backend/src
  config/env.ts      валидация переменных окружения (zod)
  auth/              проверка initData, сессионные JWT, доступ к семье
  services/          бизнес-логика: семьи, события, повторы, уведомления
  routes/            HTTP-слой: разбор запроса → сервис
  realtime/hub.ts    Socket.io, комнаты family:<id>
  jobs/reminders.ts  планировщик напоминаний (node-cron, раз в минуту)
frontend/src
  telegram/          WebApp API: тема, initData, haptics
  api/               HTTP-клиент и подписка на сокет
  features/          календарь, форма события, семья и онбординг
```

Роуты не обращаются к Prisma напрямую — только через сервисы; валидация тел
запросов живёт в `services/schemas.ts` и используется и роутами, и тестами.

### Повторяющиеся события

Поддерживается подмножество RRULE: `FREQ=DAILY|WEEKLY|MONTHLY` с `INTERVAL`,
`UNTIL` и `COUNT`. Серия хранится одной строкой, вхождения разворачиваются на
лету в запрошенный диапазон (`services/recurrence.ts`). Правка или удаление
одного вхождения создаёт запись-исключение (`EventException`), поэтому
«Этому событию» и «Всей серии» ведут себя предсказуемо.

### Напоминания

`jobs/reminders.ts` раз в минуту ищет вхождения, у которых наступил момент
`начало − reminderMinutes`, и отправляет сообщение участникам события (или всей
семье, если участники не указаны). Отправленные напоминания фиксируются в
`ReminderLog` с уникальным ключом `(eventId, occurrenceStart)` — повторной
отправки не будет даже после перезапуска сервера.

## Замечание по SDK

В ТЗ упоминался `@telegram-apps/sdk-react`. Вместо него используется
официальный `telegram-web-app.js` (подключён в `index.html`) с тонкой типизацией
в `src/telegram/webapp.ts`: нужен только `initData`, `themeParams`,
`colorScheme` и haptics — обёртка занимает около 90 строк, не добавляет
зависимость и одинаково работает вне Telegram, где приложение и разрабатывается.
Если понадобится Back Button, Main Button или облачное хранилище, SDK можно
подключить поверх — точка интеграции одна.
